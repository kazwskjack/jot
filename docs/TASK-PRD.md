# PRD 绑定与原任务执行

工作台的持续任务详情中提供 PRD 来源入口。服务器通过可选能力 `workbench.task_prd` 声明入口，执行宿主就绪后可预览和确认。PRD 正文作为原任务的固定输入，由原 DSH 理解并通过现有子任务工具拆解。

## 使用流程

1. 创建或选择已有持续任务，保留其执行角色、工具权限、触发和预算。
2. 暂停原任务，并等待原执行、成员、辅助会话、网页操作及额度预留/消耗核对结束。
3. 按详情中的静态模板整理目标、范围、验收标准和依赖，将文件保存到角色所属项目，或使用同项目对话中已上传的原始文本附件。
4. 在 PRD 入口刷新来源，选择文件的精确版本。点击“只读预览”，核对来源版本、SHA-256、原文及完整任务目标。
5. 阅读后勾选确认，再绑定到原暂停任务。此步骤固定来源副本、更新原任务目标，任务仍保持暂停。
6. 使用原任务的恢复或立即运行入口继续。原 Worker 将完整固定目标交给原 DSH/Goal，DSH 使用 `jot_workspace` 的 `tasks.upsert` 保存子任务、验收条件与依赖，使用 `tasks.next` 查询原准备度。
7. 在原执行记录和子任务账本核对进展、证据与结果。准备度和“已标记完成”不代替实际验收。

预览不会创建任务、执行、子任务或模型调用。绑定保留原任务 ID、来源对话/消息身份、已用运行次数、运行上限和累计模型预算。文件中的指令不会直接扩大权限或触发额外操作。

## 版本、回执与冲突

确认时重新检查任务、角色及来源版本。确认前文件或角色发生变化时，重新选择并预览；不会静默换成新版本。确认后源文件的后续编辑不会改变已固定的目标；重新绑定会创建独立的来源修订并保留原记录。

绑定结果未知时，页面锁住来源选择并保留原请求 key。使用“重试原绑定请求”核对同一回执，避免重复操作。服务端在同一事务提交任务更新与不可变回执；事务失败可按原 key 重试，成功后的原 key 只回放原回执。

浏览器有可用账户草稿作用域及站点存储时，同页签刷新保留来源标识、版本、摘要与请求 key，不保存预览正文，也不自动重发。不具备该条件时仅在当前页面内保留命令。不要主动清除尚未确认请求的站点存储。

如果其他入口修改了已绑定的任务目标，PRD 入口会阻断后续绑定，避免覆盖人工修改；需要先核对原任务目标，当前版本不会自动合并两份目标。

## 当前支持范围

- 支持同 owner、workspace、project 下的逻辑 `.md`、`.markdown`、`.txt` 文件，以及 `kind=upload` 的原始 UTF-8 文本附件。核对完整原始字节、大小与哈希，原附件不重复上传。
- 原始输入最多 65,536 字节。原目标、来源说明、PRD 正文及 DSH 指导合成后的完整目标最多 12,000 个 JavaScript 字符。超限会拒绝预览，不截断验收条款。
- PDF、DOCX 和其他二进制文档的正文提取未接入。
- 候选列表最多显示 200 个逻辑文件和 100 个原上传记录，超出时提示列表已截断。未显示的来源不能通过此选择器绑定。
- 项目发现策略管理的任务不能通过此入口改写目标。
- 外部 Taskmaster 安装、真实提供商的自主拆解质量及生产部署验收另行验证。

## API 与局部验证

API 位于 `/v1/persistent-tasks/:taskId/prd`：`GET /sources`、只读 `POST /preview`、带 `Idempotency-Key` 的 `POST /bind`。调用方只选择来源标识、版本和 SHA-256；权限范围由原任务角色和已认证 owner 推导。正常 actor/origin/CSRF 检查仍生效；preview 不写通用幂等账本，bind 使用自己的原子回执。

针对性检查：

```sh
node --test packages/gateway/test/workbench/task-prd.test.mjs web/workbench/task-prd.test.mjs
node scripts/verify-task-prd-ui.mjs
node --experimental-strip-types scripts/verify-task-prd-gateway.mjs
```

第一项使用真实 Gateway/SQLite；第二项使用真实 React 和合成 API；第三项使用真实 React、已注册 Gateway、SQLite 及隔离账户 relay。实际 SDK 检查是 `packages/dsh-host/test/task-prd-native.test.mjs`，需要可用的 `JOT_DSH_RUNTIME_MODULES`；未配置时的 skip 不能算作 SDK 通过。该 SDK fixture 的本地 scripted provider 只验证工具链、身份和预算，不证明真实模型质量或真实费用。

绑定的 Idempotency-Key 必须为 8–128 个可见 ASCII 字符，不能含空格。格式错误返回 422，且不会产生绑定回执或修改原任务。
