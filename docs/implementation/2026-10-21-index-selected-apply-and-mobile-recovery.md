## UI behavior

- Default configurations retain the original read-only capability shape. Only
  an operator-configured native client and a currently owned configured project
  advertise reviewed index actions, exactly stage and unstage. Capability is
  configuration metadata, never a native readiness observation or permission.
  Commit, discard, deletion and remote effects are not enabled by that flag.
- Explicit Apply admits the exact approved intent and then invokes the original
  dispatch route. Atomic admission retries retain their exact original command
  and key. Recovering a lost admission response stops at the accepted record;
  physical dispatch requires another explicit user action.
- Lost dispatch or resolution responses trigger original status/review reads,
  not automatic effect retries. A recorded application is complete only with
  original settled workspace evidence. Native JSON cannot manufacture success.
- Original server history restores an operation across reload and another
  browser page. The owner can cancel its original review and explicitly confirm
  an unfinished operation. Confirmation uses the original control request and
  frozen state digest; a changed status cannot replace an admitted command.
- Actual unknown effects remain unknown, with no rollback claim. Physical
  disposition does not imply native drain. Previously admitted controls are
  continued explicitly; a never-started original can close without a native
  client, producer or Worker. Removing native dispatch configuration does not
  remove that owner's recovery entry.
- Existing receipt pending state and before-unload warnings retain navigation
  locks. Native response uncertainty may be left and recovered from original
  server history. Refreshing history also re-reads its selected operation;
  fetching records never implicitly dispatches or resolves an operation.

## Actual synthetic evidence

The mobile test uses real React, the standalone BFF, the loopback Gateway and an
authenticated separate installed-SDK native process, not mocked native results.
It passes stage, unstage, lost dispatch response, reload without redispatch,
lost admission response and same-key retry, explicit subsequent dispatch,
another page's review cancellation while the original is paused, exact original
control and fresh native drain, lost resolution response, and reload again.
The cancelled operation preserves index bytes and inode, target worktree and
HEAD. Worker leases end at zero; actual model calls remain zero.

A further race first failed: after fresh reads observed another page's review
revocation, a stale React closure still dispatched one refused native attempt.
The backend preserved the index. The UI now checks the freshly observed exact
review/version/hash before dispatch. The regression passes without that attempt.

A cross-page history refresh also first failed to refresh selected detail.
The refresh token now requests a fresh original read without replacing the
selected operation or pending command. The actual mobile sequence passes.

Two additional mobile cases verify closed-history reload with no writes and
explicit never-started closure without a configured native client. The latter
performs only original control admission and resolution, with no native
producer/Worker or index modification. A transient repository snapshot warning
during another page's real activity is separate from operation recovery; the
test preserves that warning and scopes recovery assertions to their own panel.

The configured capability API case and all14 contract cases pass, including
rejection of false read-only declarations without exact actions, added commit
or destructive actions, and inconsistent empty configured-project lists.
These are focused local results, not full regression, production activation,
