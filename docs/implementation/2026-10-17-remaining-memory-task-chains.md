## Highest priority independently implementable closures

These are candidate batches, not assertions that parallel implementations already exist. Keep each mutation owner-scoped, versioned, idempotent and reviewable. A source-only task should not run full suites; code integration must run AGENTS-required root/Gateway builds and tests plus relevant UI/SDK checks.

1. **PRD input through original DSH tasks.** Add static goal/scope/acceptance/dependency template sections and an explicit PRD mode in `TasksPanel`/task-wizard helpers. Preview reviewed text verbatim as the existing objective (12,000-character ceiling); preserve existing optional conversation/message source. Submit existing `POST /v1/persistent-tasks` with selected role and once trigger, retaining original save receipts/run controls. The original DSH occurrence/Goal, not a new parser, produces subtasks through existing `tasks.upsert`; task identity is derived from the original bound run. Show those exact records in `TaskLedgerPanel`, including existing `next.items` readiness. UI tests cover oversize/empty input, unchanged preview, same-command recovery and no run before confirmation. One actual SDK fixture must prove original objective reception, receipted subtask/dependency writes and unchanged task-total identity; scripted provider evidence is separate from real PRD reasoning quality. No new planner, model service, scheduler or API is needed for this initial chain. External Taskmaster installation and general file PRD import remain open.
2. **Memory import slice.** New import schema/preview service, owner-scoped routes and UI, reusing `MemoryLifecycle` for committed new revisions. Independent of extraction/Dream/Always-on. Require explicit target project/private role, keep all imported content unverified, make expiry/deletion/conflict policy visible and preserve provenance without accepting authority from imported fields. Tests must include replay, rollback of failed batch and scope/tombstone refusals. This closes import only; semantic retrieval and provider acceptance remain open.
3. **Public logical-file inventory paging — locally implemented.** Original API/client/file UI now use bounded continuation with stable owner/workspace/project cursors and conservative metadata-drift refusal. See implementation evidence below. Internal Always-on full source capture remains separate. Tree/download/lifecycle previews, deletion and binary operations are still separate work.
4. **Current scheduling acceptance and explicit missed-trigger display.** Exercise existing coalescing rules under fake clocks, restart, competing connections and DST; expose documented next-due/coalescing semantics in the existing preview/task details. No second scheduler, cron parser or new background authority. Separate optional cron work from this bounded closure.

Do not group idle Dream, Web Push or destructive project deletion into a small generic CRUD patch. They require explicit policy/subscription/retention authority and recovery contracts. They can be designed independently, but should not be declared shipped from route scaffolding.

## File-list paging implementation evidence

Implemented in this working tree after the initial source audit: original Gateway `GET /v1/workspaces/:workspaceId/files?project_id=...` accepts optional canonical integer `limit` (1–200, default 200) and `cursor`; response retains `.items` and adds nullable `next_cursor`. Existing run-scoped `listFiles(owner,workspace,project,runId)` calls retain their arguments and default bounded behavior. The original `files.list` tool argument schema is unchanged; no change to discovery source collection, Worker, execution authority or native file writes.

`workbench/file-list.ts` streams only logical file metadata in one read transaction and orders by SQLite BINARY path. A domain-separated HMAC uses the existing private persisted conversation cursor key; the cursor binds owner/workspace/project, whole-current-metadata digest, last path and original 24-hour expiry. A changed scoped inventory rejects continuation with `FILE_LIST_STATE_CONFLICT`; there is no retained historical filesystem snapshot or silently mixed list. Under an unchanged inventory, keyset pages traverse every unique path once. Any later file-content open still uses the original current-version read contract. Listing no longer creates a project/blob directory or requests a writer transaction. It works while another connection holds a writer reservation.

`workbenchApi.files`, typed page/options and the original Files section now provide explicit load-more/refresh controls. A scoped pager aborts and ignores old responses after project/workspace switch, refresh or unmount. Network failure preserves earlier pages for retry; expired/changed cursors clear the mixed result and require refresh. File paths render as escaped text. The implementation scans O(N) metadata per page to detect drift and holds only bounded page output; it does not introduce another authoritative revision counter. Large-project throughput, DOM virtualization and retained snapshots are not established by these tests.

Red/green evidence: the new 405-file regression first failed with `200 !== 405`, then passed through all pages. New file-list suite: 7/7, including real GET, >200 traversal, custom bounds, cross-owner/project/workspace and tampered cursors, update/delete/insert drift, writer-reservation read, independent-connection reopen, expiry, legacy run-scoped calls and response contract. Gateway contracts/routes selected run: 12/12 before two additional pagination cases were added. UI/client/pager/SSR selected run: 14/14. Gateway `tsc --noEmit` passed. No full suite/build, real provider, browser/production rollout, commit or push was performed for this slice.

The additional existing Workbench service suite produced 14 passes and two failures at Windows `symlinkSync` with `EPERM` before their intended assertions. Those environment permission failures were preserved, not converted into skips or reported as passing. The new fixture briefly failed cleanup because a second DB connection was closed after its directory cleanup; closing it in the test's `finally` fixed that fixture and the final 7/7 run passed. The full workspace/project capability remains incomplete as detailed above.

During the parallel PRD integration, the combined selected Gateway rerun reached 13/14: all seven pagination cases and the file route passed; the shared contract declaration test observed the newly added `TaskPrdPreviewRequest` schema before its matching TypeScript declaration had been appended. That shared integration intermediate state was reported to its owner rather than changing the other feature's contract. Final combined contract verification belongs to the integrating run.
