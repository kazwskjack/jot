# Original reserved native index execution

The original internal executor previously refused its own held project
reservation, so admitting an operation and reading a native family could not
reach physical index effects. `GitIndexExecutions.performReserved` now joins the
original native source host to that same executor. The DSH planner, original
review/admission, Worker lease, kernel, journals and cleanup remain in place.
No HTTP mutation route, scheduler, new runtime or production switch is added.

## Original custody through effects

The original owning composition supplies the actual native source host and its
context inspector at construction, not in a request body. This path rejects an
unconfigured host before reserving or starting an effect producer. It reserves the original
admitted execution and derives the complete family from its original journal.

Inside the original awaited maintenance callback, it verifies the issued source
context, exact family, active startup admission and actual configured root. A
process-local object retains those live checks only for this original execution.
Copies or operation identifiers cannot create that custody. The generic shared
workspace write check is unchanged; the ordinary uncoordinated executor still
refuses a held reservation.

Original preparation, exclusive file placement, dispatch and publication each
retain the synchronous owner/review/source checks, exact Worker lease and live
native checks. The original kernel continues to verify index/file witnesses and
publish only the selected index bytes. The actual native cancellation signal is
combined with caller cancellation and reaches preparation and kernel operations.
An async startup check cannot replace this synchronous physical authority.

The native pre-storage startup guard must have mounted before eager or resident
Agents, remain active, and belong to the same original Host as the held factory.
Readonly source inspection without that guard does not authorize physical effects.
Disposing it during preparation revokes the effect authority.

## Physical placement and source boundaries

`retainNativeWorkspaceRoots` observes the actual operator-configured repository
directory identity. Resident/cold native cwd must resolve to that original root
without symlink substitution; the retained check detects physical replacement.
An absent Session has neither a cwd nor a header digest. Caller mutation of the
observation array cannot change retained placement.

This increment implements the original local composition when native maintenance
and the configured tree are genuinely held in the owning process. It does not
turn a remote/cached inventory into local custody or load another DSH runtime.
Isolated work, logical immutable files and configured checkout remain separate:
an unrelated directory is refused before any lease or producer is acquired.
No shared/isolated file is copied as an implicit side effect of staging.

## Original settlement

On success, the original kernel cleanup, producer finish, Worker lease release,
native final source check and maintenance drain must all return before settlement.
The original database transaction then records immutable outcome/producer/finish
digests and releases the original reservation. Historical success remains the
same receipt and does not reenter native maintenance or repeat staging.

An interrupted callback, lost native acknowledgement, failed settlement write or
failed release write keeps the reservation. A known applied row alone does not
cause automatic release on a later request. Settlement and release roll back
together. A replaced Worker retains its own lease; the former producer cannot
publish or delete that replacement through native custody. Pre-dispatch release
remains separate and cannot erase started producer evidence.

## Verification scope

Focused real local Git and installed-SDK tests cover actual stage/unstage under
original maintenance, exact history after database reopening, different native
directories, cancellation, review revocation, replaced Worker ownership and
interrupted acknowledgement/settlement. An additional startup/Host-provenance
gate covers missing, disposed and asynchronous admission checks.

The cancellation fixture uses the SDK's official `{kind: 'user'}` cause. An early
diagnostic supplied an invalid Error object and timed out; that fixture was
corrected before reproducing and fixing the actual missing signal propagation.
The timeout is not counted as upstream runtime acceptance evidence.

The complete Git and workspace-member regression passed all 178 tests with the
installed SDK enabled, without skips, failures or cancellations. It includes
the original real-process crash, lost acknowledgement, lock ownership and
recovery cases as well as the new native lifecycle cases. Complete adapter
regression passed 806 tests with 29 conditional skips (835 total). A separate
installed-SDK maintenance/admission regression passed all 43 tests without skips.
The standalone root passed 67 tests and its Vite build; Gateway typecheck passed.

The final frozen-source Gateway regression completed with 2,103 tests: 2,084
passed, 19 conditional skips, zero failures and zero cancellations. Its optional
installed-runtime cases are distinct from the real-SDK-enabled 178-test and
43-test gates above. Conditional skips are not acceptance evidence, and these
gates do not close the full Git or product capability.

## Still required

Join original shared/isolated publication provenance and its separate review,
checkpoint restore, explicit reconciliation/settlement of interrupted outcomes,
and actual cross-process hosting without serialized custody substitutes. Then
connect the original HTTP/BFF/contracts and mobile execution/disposition controls.
Mixed old native producers must drain before activation. The full 26-capability
and portable Chat/Work ledger remains open, as do commit/destructive/revert and
remote repository operations. Production behavior is unchanged by this source
increment.
