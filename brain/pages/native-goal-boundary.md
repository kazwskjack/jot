DSH remains the authority for ordinary Goal state, automatic rounds, planning and completion. Gateway projections and human control receipts do not create another scheduler or grant tool permission. Human pause/stop and the original owner, Session, high reasoning and cumulative accounting remain authoritative. Role and persistent-task Goals keep their existing scoped paths.

Persisted Goal reads use official cold projections without creating an Agent or rearming activation. Explicit cold pause/clear require an ordinary preset, empty durable inbox and contiguous balanced logical history, then official resolver/maintenance/persistence. Pending/claimed input and a still-open attached turn are recovery requirements, not proof that there is no Goal. A persisted interrupted tail with empty pending inbox is already supported by the locked SDK: cold Session Query supplies logical conservative closers without changing storage, and the original resolver durably appends them. Real Host regressions cover an open turn plus started/unstarted tool requests, fixed unknown/not-started results, original-run continuation and another cold restart. Seeded histories are not additional real in-flight tool process kills. No Jot repair algorithm or manual log rewrite is needed.

Human resume is a durable intent in the original database, run queue, outbox and Coordinator lease, not a model prompt. Its continuation run has null input_message_id plus explicit goal_control_id and source-run lineage. The original user message and attachments are not replayed; candidate attribution follows the source run. Null input prevents a historical input-message join from obtaining the source prompt, but does not prove an old Worker can execute the new job. The whole consumer pool still needs upgrading before rollout.

Public resume admission atomically commits the original request, queued run and exact-key 202 acceptance receipt. Acceptance, native applied receipt and Goal completion are different facts. Lost replies recover only the original durable receipt; a typed pre-admission reservation can retry its original request without a duplicate job. Readiness reports configured capability and original queue facts, not a complete rollout audit or recoverability guarantee.

The trusted Host subscribes to official follow and parks its iterator at the opening snapshot before restoring an Agent. In the locked SDK, advancing beyond that snapshot promotes a prepared Session; preflight and exact native maintenance must admit that advancement. Cold observations and rejected pending input must not create an Agent. Native CAS, persistence flush and an applied receipt precede model execution. Every original step/tool/model path checks the live observer, original lease and current Goal identity; an old receipt cannot authorize a replacement Goal. Same-Goal completion still allows its closing answer. New Hosts/followers cannot rearm an old unknown dispatch or receipt.

The UI follows accepted original runs separately from validated native Goal phase and continues polling while restoration is queued. Unknown replies persist minimal owner/conversation-scoped control metadata through strict IndexedDB transactions before POST and acknowledgement. The original localStorage read-back was insufficient: a real whole-browser process-tree termination lost its unconfirmed command. Await strict transaction completion; unavailable strict storage fails closed. Legacy pending commands migrate without resending, and durable migration tombstones prevent failed local acknowledgements from resurrecting them. Fresh scope checks, separate per-command keys, serialized writes and acknowledged tombstones preserve explicit original-key recovery. No objective, message, credential or native phase is stored in the browser journal. Both renderer-crash and owned whole-browser process-tree termination/restart recover the exact original key in real local browser probes, without automatic POST or storage export/reinjection. Clearing site data, storage eviction and OS/power-loss behavior remain separate limitations. All-boundary server-process reconciliation, pending/claimed-input and unsupported attached-history recovery and production acceptance remain incomplete. Gateway admission and Host observer switches default off until complete consumer rollout and remaining gates pass. Real locked-SDK/scripted-model verification is wiring evidence, not real-provider quality or production accounting.

Only the original trusted live attempt before invoking native resume may attest an immutable not-called rejection. The Gateway records its fixed reason with the exact original run/Session/lease; Worker and UI expose that reason without raw transport text. A lost begin acknowledgement can be reconciled as not-called only by that still-live attempt. Once native resume has been invoked, a thrown error, failed flush or lost applied acknowledgement is uncertain and cannot be reclassified from the current Goal alone. Disarm covers a native invocation that appended then threw. Actual isolated Host termination is tested after native flush and after applied commit, distinct from unit fault injection or exhaustive crash recovery.

Dispatch identity also includes a Host-generated immutable observer ID. Begin, applied and pre-native refusal bind that same ID, even within one unchanged Worker lease. A delayed old observer cannot reject or apply a replacement observer's dispatch. Existing uncertain/applied records gain a null observer field, never a retroactive execution grant; the original request and receipts remain unchanged.

Observer revocation cancels only its same-Goal in-flight work using the official keepInbox option. Default Agent cancellation would durably clear later human inputs, so it is not appropriate for observer loss. Pending queued/steering input must remain unchanged, and no replacement Goal may be cancelled by an old observer. Same-Goal paused, blocked or complete state does not prove its model/closing request is idle. The real Host probe parks two synthetic inputs during one in-flight model request, disconnects, explicitly flushes and restarts, then verifies both input IDs persist without another Agent/model request. This is not original-product-run replay authorization, unflushed power-failure recovery or production acceptance.

KeepInbox does not protect a batch already claimed before native pre-step entry. While an original observed pre-step remains live, observer revocation synchronously preserves its unentered human inputs before its own cancellation, using the official Goal driver's next-step convention and original IDs/content/RPC source. No send, new prompt or wake occurs; generated Goal rounds/context and committed message IDs are excluded. An already-aborted native step is not restored, and a later explicit cancellation can discard restored input. Identical pending records are not duplicated; conflicting content or unavailable history produces a fixed unconfirmed recovery error without overwrite. A real Host lease-revocation/flush/restart probe preserves the once-claimed input with zero model requests. This does not authorize arbitrary cold claimed-input replay or replace original-run/owner/lease/composition/accounting recovery.

Observer/lease loss is an owning-execution cancellation and uses the official parent cause, not user. Only actual user stop paths should be described as user cancellation. This changes the current cancellation event classification; it never rewrites historical immutable receipts or grants resumed execution.

Ordinary original-input recovery now has a read-only internal product binding endpoint. The existing service identity and a transaction prove the running original human run/message, database-derived owner, current Session and exact Coordinator lease; workbench and message-free Goal runs are rejected. Its stored product content digest is not native attachment equivalence, and execution_authorized remains false. This identity snapshot cannot wake a driver, reserve model cost or replace tool permission. The optional original-input Host now consumes this binding through audited preflight; Opt-in Runner selection and original publication now pass the local Controller case; native claimed input, monetary reconciliation and deployed acceptance still need implementation or verification.

The locked upstream Controller cannot wake an already accepted pending RPC, and its driver wake is private. An explicit optional Jot compatibility transform now adds an exact-sequence/exact-pending-ID/exact-human-RPC wake capability behind original native maintenance, without inbox mutation or a new prompt. It uses the native driver latch and honours native cancellation. The prepared package must retain the complete audited setup hooks and exact pinned upstream bytes; partial/modified packages are refused and the default package preparation remains unchanged. This is a Jot extension, not an upstream API. Real local SDK tests cover attached-input consumption once and cancellation before execution; cold original-run recovery, Host/Runner integration, composition/permission/accounting and production acceptance remain incomplete. No installed live runtime is modified or feature enabled by the transform.

Original-input resume preflight now joins original product binding to exact cold native pending human RPCs before Agent resolution. Clone/freeze native projection and history before asynchronous checks: a shared mutable projection otherwise allowed changed content to replace verified input. A trusted actual observer assertion and cold/bound historical-composition audit with an unchanged fingerprint are mandatory, with no permissive default; repeated checks retain original lineage/lease and unchanged native sequence/inbox. This packaged preparer does not open a stream, restore claims, grant execution or wake a driver. Historical production composition, cumulative cost reconciliation and full recovery/deployment acceptance remain incomplete.

Preserving inbox input does not revoke an existing native maintenance wake: parent cancel with keepInbox can still start that driver. The optional compatibility package now supplies separate pending-wake revocation protocol 1. Each latch returns a fresh non-enumerable readonly process-local Symbol token; only that token can revoke its owned maintenance wake, without clearing input. Same IDs/RPC/sequence cannot identify a later wake attempt. A subsequent independent native wake invalidates old ownership, and stale/forged tokens cannot cancel it. Real SDK regressions first reproduced both continued execution after parent cancellation and old-request revocation of a later identical wake, then passed with token ownership. Preflight requires both wake and revocation capabilities. This is local native cancellation infrastructure, not completed HTTP Host/Runner/accounting recovery or production enablement.

The optional ordinaryInputRecovery Host now owns a parked native follow and exact original-run lease, invokes preflight/maintenance/wake without a prompt, retains local wake-token custody, and guards pre-step/tool/model entry. Maintenance disconnect revokes the exact wake before parent cancellation with keepInbox. Unconfirmed native wake cannot admit a provider; known unentered human claims are retained before cancellation. Native idle releases ownership, and a later foreign human delegates after detaching the old observer rather than rejecting the new task. Host acknowledgements are neither completion nor durable replay receipts. Route/lifecycle fixtures and the local installed-Controller HTTP recovery cases pass, but production composition audit, full consumer upgrade, steering ownership, claimed recovery, monetary reconciliation and deployment acceptance remain incomplete; configuration and both Goal switches stay off by default.

Installed-Controller HTTP recovery now has three real local SDK cases with original Gateway/Coordinator records: execute once after hard Host death and original-run lease replacement, refuse an obsolete lease before Agent creation while retaining input, and cancel a held model request on observer disconnect. A further restart preserves the expected inbox without Agent creation and rejects vanished observer authority. The synthetic pending input is seeded by a test wrapper, its composition audit is fixture-only and its local provider is scripted; initial production prompt admission, historical production composition, cost settlement and canonical Worker publication are not proven. Human counts use source.kind=user rather than all user-role context events. The isolated passing Loader overlay disables the old agent-loop entry and inserts the prepared compatibility plugin; a name-only replacement did not change actual Agent capabilities in the first experiment. No live runtime is edited.

Opt-in original ordinary-run recovery now connects Worker, SessionControllerClient and Runner to the observed Host. A generation>1 ordinary run uses its stored owner-bound Session and exact original message/lease; it skips create/prompt/input attachment replay/context staging. Missing original Session or mixed-version Runner interrupts without prompt fallback. Exact acknowledgements and separate Goal/ordinary execution metadata are checked. The original binding, including input content hash, is rechecked before readiness/projections and within canonical publication. Real installed-Controller testing now reclaims one original run, makes one scripted model request, preserves one original human and native usage receipt, publishes exactly one canonical answer, and does not repeat after a further poll/restart. Cold original-input recovery alongside persisted active/complete Goals is verified without implicit rearming or changing their identity/revision/phase/rounds; paused/blocked Goals refuse before Agent creation or inference and preserve the original inbox. The native Goal service resets activation on attachment, and the native round driver requires active plus armed: inbox wake does not authorize Goal resume. Explicit Goal rearming after recovered input, historical provider-cost/unknown settlement, claimed restoration, steering and production composition/rollout gates remain. GENERAL_AGENT_ORDINARY_INPUT_RECOVERY_ENABLED defaults false.

普通聊天的 claimed 输入还原现在有独立的 unpublished-factory 校验层：沿原 Gateway owner/run/Session/input hash/lease，校验原消息 RPC、全消息指纹、Session createdAt 与历史 admission/configuration 指纹，再调用原生 append-only 还原算法。消息的历史受理证明必须先于中断存在，不能在恢复时根据当前日志补造。真实 Gateway/SDK 硬退出验证了落盘后发布、重复硬退出后零重复插入和错误身份/配置/admission 的拒绝，且没有模型调用。工厂还原始终不授予执行权；普通 HTTP claimed 恢复仍拒绝，尚须接入原 Controller 消息受理存储、原工厂前后配置审核与观察中的 Worker 执行，之后才能开放。普通销毁会取消 inbox，不得当作崩溃测试或复活已取消消息。
