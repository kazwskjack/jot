Project discovery covers the full lifecycle: explicit owner project/workspace/role policy, factual idle/source collection, original occurrence admission, DSH planning and native task/Goal execution, source-backed plans, isolated work cycles, verified reports, reviewed diff/apply, pause/stop and deployment recovery. Configured persistent tasks are not equivalent to proactive discovery.

DSH remains the sole planner. Reuse Gateway ownership, role epochs, permissions, original runs/leases, budgets, receipts and channel outbox. Do not transplant the reference implementation's unattended bypassPermissions or treat absent channel leases as proof of native idle. Pure gate results are non-authorizing advice; fresh live authorities must be revalidated transactionally before admission. Unknown/stale facts block. User pause/stop and unknown model/tool outcomes stay authoritative.

Default policy is off. Discover-only produces proposals; discover-and-work still requires bounded owned workspace/tool authority. Applying an isolated cycle to the original project always requires explicit review of a frozen diff/base and idempotent owner confirmation. No automatic new planner, ordinary-chat prompt replay, fresh-budget escape or resurrection of revoked memory/permission.

Honor explicit unlimited budgets. Persistent tasks now accept explicit public max_runs:null, with capability-gated UI and an exact internal (unlimited,0) tuple in the original table; finite/default100 are retained. Migration preserves original IDs, counts, states and request keys. Zero alone is not unlimited: tuple guards reject inconsistent writes and the known prior numeric admission guard refuses unsupported new tasks. Full old-worker rollout/rollback still needs acceptance. Changing limits never resets usage or automatically resumes an exhausted/paused task. Model budgets, native Goal, mailbox quotas and physical background capacity remain separate. Null in discovery gate cycle capacity means confirmed unlimited policy, never missing or guessed facts. This prerequisite does not install the discovery pipeline.

The initial pure eligibility module and the opt-in current-Host native observation protocol are implemented. The project activity source adapter combines original scoped SQL and existing workspace facts with the strict authenticated Host client, releasing read transactions before IO and rejecting drift or expired observations. These are non-authorizing source components, not a running discovery feature. Durable owner policy configuration/control API and immutable internal signal storage are also implemented. Saving starts off; role drift revokes effective activity; only explicit owner enable can resume. Original atomic API receipts and immutable business revisions prevent duplicate writes after lost responses. Signals never resume paused/stopped policy and exclude self-generated origins. Original task-budget and Coordinator logical-capacity read observations are implemented without allocating calls, scopes, leases or another scheduler. Exact durable-root usage includes members; unknown and in-flight usage remain unresolved for a new occurrence. These observations are not execution authority or native/hardware readiness. Explicit owner enable now prepares one fixed original task/budget identity atomically with the policy command, with no due time or occurrence. Pause/stop/resume reuse it without resetting the accumulated run count. Generic mutations, timer and legacy occurrence paths are guarded; legacy occurrence insertion remains refused, while the trusted internal planning controller can now commit an exact reservation and original occurrence together. Automatic discovery dispatch remains uninstalled. Remaining reconciliation facts, trusted physical watchers/provenance, failure/wait/recovery, isolated workspace/apply, full policy/work-cycle UI, real-provider and deployment acceptance remain incomplete. The source review and entire implementation sequence live in docs/superpowers/plans/2026-10-17-always-on-discovery.md. Full PilotDeck capability scope is unchanged.

Trusted database source ingestion now runs on the existing ready Worker maintenance loop. It journals role-bound human input identity metadata and owned immutable file-version metadata without reading bodies/blobs, creating runs or reserving a model attempt. Original cumulative task budget lineage excludes recorded discovery-derived outputs across the project; unknown producers hold later versions of that path. Direct owned versions without producer records are base metadata, not human-authorship proof. Off/stopped/revoked policies do not collect; paused policies never resume. Bounded drain batches are not task/token caps. Physical filesystem watchers, edited-message revisions, failure/wait/recovery, automatic lifecycle dispatch and all remaining work-cycle/apply/UI/provider/rollout acceptance remain open. The SQL occurrence guard now requires the exact immutable reservation and current policy/task/source identities; legacy calls remain refused.

Original planning admission now coalesces a source head into one original task occurrence. Exact observer-issued native idle receipts are revalidated synchronously under the original transaction with current policy/role/source, original budget/accounting and Coordinator capacity. Deferred occurrence FK prevents orphan reservations. Competing fixture processes create one queue entry. Planning workspace mutation, messages and delegation are denied, and policy/role drift or stop revokes execution. A normal original admission hold is not a dispatched model call. This trusted controller is not a public/model tool or an installed automatic dispatcher. Discover-and-work, real-provider execution, isolated work/reviewed apply, UI and rollout/full inventory acceptance remain incomplete. Structured plan/report contracts now reuse original workspace and completion flows.

Original workspace operations now provide paged discovery context/proposal readback, on-demand pinned source text (no image fetching), immutable normalized-work/source-deduplicated proposals and report revisions. Own task steps/evidence/assessment may advance while project/memory writes, messages and delegation stay denied. Actual receipted contiguous source ranges determine coverage; no-plan reports require the full current batch. The server derives the complete proposal manifest, including beyond a bounded caller list. Current report proof binds source, role/policy, lead, steps/input and all proposals; stale reports cannot complete. It enters the original frozen Goal/business review/certificate snapshot, never a parallel acceptance flow. Recording alone is unaccepted evidence, not publication, accepted dormancy, application or automatic execution. Dedicated local SDK cases now verify original acceptance as described below; real-provider/production acceptance and remaining full lifecycle remain open.

Accepted no-plan dormancy is derived read-only from the original admission, frozen report/candidate, owner business certificate/review, native Goal completion proof and committed assistant message, with exact identities and hashes. Neither a report, review nor completed status alone is sufficient. Invalid proof is unknown; absent or foreign tasks are never accepted predecessors. Unchanged source revisions remain dormant; new owned revisions can queue the same original task and cumulative budget only through current original admission checks. A restart may reconcile original native completion but never invent acceptance. Local official SDK canaries use a scripted model and do not establish real-provider quality, automatic dispatch or deployment acceptance. All remaining full lifecycle and full inventory requirements remain open.

Recoverable discovery source failures are not role revocation. The authenticated original bridge may expose only exact repairable source/report conflict codes on their matching tool or completion-proposal endpoints, never server detail text or arbitrary errors. Corrupted pinned bytes and expected missing files produce bounded discovery-source reasons, no successful source receipt or coverage, no completion or dormancy. Permission, owner, stale source and revoked role failures remain fail-closed. DSH can use original native wait/reply/checkpoint continuation and the same task/Goal/cumulative budget after repair; no alternate status loop or automatic authority restoration is introduced.

Initialized conversation/snapshot reads must not request writer locks merely to reopen an existing cursor key or default project. Missing initialization remains atomic with locked recheck; legacy NULL project migration remains explicit and owner-scoped, corrupt keys fail rather than rotate. Keep snapshot read consistency and cursor signature identity; do not replace contention repair with blind retries or weaker signing. Role-bound discovery policy UI configures the existing off-by-default owner policy through original receipts, with explicit enable/pause/resume/stop and same-command recovery after lost response. UI configuration is not automatic dispatch or work-cycle execution authority.

Isolated snapshot manifests, creation/inspection receipts and exact base/result differences are non-authorizing artifacts. They use explicit trusted roots, relative selections, binary streaming and frozen hashes; structural ancestors are containers only and never become replace/delete authority when selecting a child file. Unique exact content can establish a rename; ambiguous repeated bytes remain add/delete. Keep original source untouched. Known private path refusal is not arbitrary secret-body detection, path/inode checks are not OS sandboxing, and checks of a live tree are not an atomic filesystem snapshot. Provider instance capabilities can be reissued only through a trusted durable original-cycle journal and real artifact/root verification. One immutable preparation intent binds the exact accepted original proposals, owner scope, original cumulative budget identity and trusted host configuration; a missing ready record remains uncertain and never automatically recopies. Artifact recovery is not execution permission, current physical base validation or reviewed apply. Owner history is a pure paged projection of original runs/reports/certificates/native completion/publication, not another status store or an authorization source. Model summary text remains untrusted and may quote source content; omission of raw source/root fields is not DLP. Git provider, original DSH isolated execution, scoped memory, exact reviewed apply/reconciliation, automatic dispatch and complete deployment/scale acceptance remain open.

Logical Workbench files are the default project source: capture all owned immutable version facts and raw bytes, pin one private base before snapshot intent, and materialize directly into the original isolated provider. Logical blob containers are not project trees. Current-base metadata and actual bytes must both be checked; historical planning evidence is separate from the current base. Project-scoped file revisions cover inserts, updates, deletes and scope moves without treating unrelated database writes as source changes. Stable inventory caching never caches byte verification or current authority, and uncommitted schema validation must not survive a DDL rollback in memory. New target absence is explicit; copied context does not expand plan-only write authority. External Git roots, original DSH work occurrence/isolated execution and reviewed apply remain distinct unfinished requirements.
