# Key flows

## Memory flow
New completed public messages become owner- and role-scoped source batches. The optional pinned extractor uses a dedicated original processing run in the original pool's idle fallback. It proposes durable facts with source references; owner approval writes versioned private memory. Retrieval uses authorized current records. Reviewed project knowledge is maintained separately as Markdown.

## Integration state
The capture kernel, owner policy/list/detail/collect/apply/reject APIs, native pending/read/propose tools and workbench review are connected. Optional plugin loading verifies reviewed bytes; its Host uses the original budgeted LLM at high reasoning without a duplicate toolset, prompt injection or planner. Source cumulative budget scopes, original leases, role idleness and cancellation remain enforced. Lost replies can reconcile committed proposals and known usage; unknown usage is not retried blindly.

Actual SDK/plugin tests use a scripted model and do not establish real-provider quality, exhaustive crash recovery or production readiness. BRAIN.md makes no model requests and is not another conversation extractor.
